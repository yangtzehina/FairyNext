# 法定帧协议：唯一相位词表

> [!warning] 为什么需要这一篇
> 对抗评审最高危发现：8 份子系统设计用了**四套**帧相位词表（P1-P7 / P0-P9 / SimEnd→Resolve / ①-⑥），接缝各说各话，集成第一周必然爆炸。本表为**法定唯一词表**，所有子系统的钩子逐一钉进编号。宿主只调一个入口：`UiKernel.Tick(in FrameTime)`（Unity 后端挂 LateUpdate）。

## 相位表 P0–P9

| 相位 | 名称 | 做什么 | 用户代码 |
|---|---|---|---|
| P0 | 输入 | 排空 `PostInput` 队列 → 命中测试（上帧已收敛的序）→ 事件链派发（capture/bubble） | 回调可写状态（只 Mark）/入命令队列 |
| P1 | 时钟 | `Clock` 定时器按创建序推进（三时域：Scaled/Unscaled/Manual） | 回调同 P0 约束 |
| P2 | 全局失效窗口 | 挂起的全局失效在此统一生效并 Mark 依赖（字形库 generation、ScreenSize）——排水期间禁翻转 | 禁 |
| P3 | 命令排空 | CommandQueue FIFO 执行（≤4 波，超限延帧 + 责任链诊断） | 命令体自由写状态 |
| P4 | 状态 | `Binder.Flush`（四件套）→ `TickTimelines`（tween/时间轴推进，写 anim 通道）→ `Resolve`（合成写 authored，纯数据不跑用户代码） | 仅 Binder apply 闭包 |
| P5 | 布局排水 | 四层串行：度量（文本 Measure，只量不出网格）→ 包围 → 约束图拓扑序单遍 → 流式布局；随后**受控回调窗**：虚拟列表铺设、滚动补偿（≤3 轮有界微排水）。唯一写 resolved | 仅受控窗（IListSource.Render 等） |
| P6 | 结构与视觉定形 | paintOrder 脏父切片拼接（structEpoch++）；world 矩阵 + worldVisual（α积/visible AND/grayed OR）沿脏子树一遍算；向下通道子树戳下钻 | 禁 |
| P7 | 渲染排水 | 流消化五通道：content 局部重写（slack 内）/ transform 槽或 tier-2 / color 基色重乘 / visible 隐显 / structure 整流重编（MVP）；文本此刻出 quad；孤岛同步；失败沿阶梯降级 | **禁**（debug 断言，release Mark 入下帧） |
| P8 | 提交 | 单元 sortingOrder 从 paintOrder 派生（下标×16，structEpoch 变才重推）；每段合并区间一次上传；段属性块集中写（firstMaterialInFrame 隐契约显式化）；字形增量上传（预算封顶） | 禁 |
| P9 | 帧尾 | 诊断锁存；**句柄统一换代**（Destroy/Pool.Return 均为标记即死、此刻 gen++，同帧事件链安全）；AfterFrame | 钩子 |

## 一次 setter 到像素（按通道）

| 写入 | 通道 | 消费相位 | GPU 动作 | 延迟 |
|---|---|---|---|---|
| `img.Frame = 3` | content | P7 | 叶 quad 原位覆写 + 区间上传 | 当帧 |
| `n.X = 10`（普通叶） | transform | P7 | tier-2 重 stamp rect | 当帧 |
| `panel.X += v`（tween/滚动） | transform→槽 | P7 | 只写槽矩阵数组一项 | 当帧，零重建 |
| `n.Alpha = 0.5` | color | P7 | 从 CPU 侧未乘基色重算 color 场 | 当帧 |
| `c.AddChild(x)` | structure | P6+P7 | paintOrder 切片拼接；所属流重编 | 当帧 |
| `n.Width = 200` | layout | P5→派生 Mark→P7 | 经 content/transform 落地 | 当帧 |
| `c.Grayed = true` | 向下（子树戳） | P6→叶 Mark→P7 | 叶 flags 位重标 | 当帧 |
| 字形库换代 | 全局失效 | 下帧 P2→P5/P7 | 正常排水路径 | **下帧**（唯一跨帧项，换取永不画错半棵树） |

## 重入契约（逐相位明文）

- **P0–P3 自由**改状态：没有任何排水在进行，Mark 是 O(1) 幂等的。
- **P4** 波次 + Binder 四件套收敛（上限内同帧、超限延帧可诊断）；Resolve 不跑用户代码。
- **P5** 受控窗有界微排水（≤3 轮）兜住虚拟列表 realize / 滚动补偿的副作用。**v1.1 增补——P5 幂等断言**：同 authored + 同约束图连跑两次 P5 必须 bit-identical；debug 构建断言 P5 内禁读上帧 resolved（滚动补偿窗除外）——LayoutNG 治 hysteresis 的教训，把裁决 1 从规则升为机器可验。**v1.3 增补——不变式快路径**：受控回调满足「只写本次排水尚未访问的子树」者 realize 内联进单遍（Flutter 交错 build/layout 合法性论证移植；固定物理节点集天然满足）；≤3 轮上限降为违例时的兜底，debug 断言检查。
- **P7/P8 禁改**：debug 构建 setter 检测 `CurrentPhase >= RenderDrain` 即断言；release 下 Mark 照记但入下帧队列（不丢、只延迟）——把旧架构「onUpdate 里改属性碰巧能用」的未定义行为变成明确契约。
